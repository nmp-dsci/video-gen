pipeline
Preview: H3 with the PDMD 4-step speed LoRA makes a 672×384 clip (16:9) with 32 kHz stereo audio. Upscale: Open-H3-Regenerate-2K (NVIDIA's open replacement for MiniMax's hosted 2K stage) runs its latent upscaler, then 2–3 steps with its refiner LoRA, to 720p, 1080p or 2K. The preview's soundtrack is kept.
engine
Cell 2 writes run_h3_2k.py (3,352 lines) on top of WanGP pinned to b8b18f81 (1 Oct). Every transformer block is split across the two T4s, the text encoder and VAEs run on GPU 1, and VAE decoding is shared between both. It exits if torch.cuda.device_count() < 2.

2 · The decision

Three ways onto one L4

All three aim at the same thing: H3 video with audio, plus the 2K pass, on one 22.5 GB GPU.

A · Port AIQuest's engine not recommended

Keeps his UI and his tuned tiling. But the two-GPU split and the shared decode would have to be rewritten, and the engine never streams weights: the 21 GB transformer plus the 3.1 GB refiner LoRA don't fit in 22.5 GB at once.

Cost: days of work on someone else's 3,352 lines, redone whenever he updates them.

B · Run WanGP itself recommended

The same H3 code the notebook drives. Its default memory profile (Profile 4) keeps the main models in system RAM and sends them to the GPU part by part, which is how it runs models bigger than the card. It has the 2K regenerate built in, H3's speed profiles, Ref2VA with voice references, and a headless mode (--process settings.json) for repeatable runs.

Cost: one install cell and one launch cell. The risk is the install on Colab (step 3).

C · ComfyUI on Colab later, for M2

Where s00's harness ends up: workflow JSON submitted from code, later on Modal. The H3 templates are built in, but the 2K pass needs a community conversion of the refiner LoRA and, in an RTX 5090 test, about 32 GB of VRAM. On 22.5 GB it would lean on ComfyUI's offloading.

Cost: more wiring now. Worth it once the harness exists.

Recommendation: B. It's the shortest path to the same outputs on one GPU, and it keeps the test about H3 rather than about porting code. C becomes the right move when M2 needs workflows the harness can submit.

5 · Risks

What could make this plan wrong

The install on Colab most likely

Colab's Python and NVIDIA driver may not match WanGP's recommended stack. The probe in step 2 decides which stack to use, and the separate Python keeps Colab's own packages out of it. If the full requirements won't install, use the H3 subset.

Memory at 1080p and 2K

53 GB of RAM is a 2024 figure. On Linux, WanGP pins up to 60% of RAM by default. The 2K pass peaked at about 32 GB of VRAM in a ComfyUI test on a 5090. WanGP spills to RAM instead of crashing, but slowly. Start with 5–8 s clips at 720p and 1080p, and use --max-ram if Colab kills the runtime for memory.

Sessions end and take the disk

Paid sessions run for at most 12 hours and time out when idle; Colab doesn't publish the idle limit. Weights re-download each session (10–20 min, about 0.5 units). Buying more Drive space doesn't enlarge the VM's disk, so keep only outputs on Drive.

L4s are not guaranteed

Colab sells premium GPUs "subject to availability", even to paid users. There's no thousand-place queue, but some days the L4 may be missing. Then an A100 (40 GB) is the fallback, at about 5.4 units an hour.

Speed is unmeasured

On paper an L4 has about twice one T4's compute, but the notebook uses two T4s at once and WanGP streams weights. Expect Kaggle-like times, not faster ones, until session 1 measures them.

Colab's rules

Every runtime bans deepfakes and connecting through remote proxies. Without units, Colab also bans working mainly through a web UI. Colab's own port proxy (step 4) keeps the UI private, with no public link.
